\begin{abstract}
LLM serving slowdowns are often diagnosed from aggregate latency and scattered
logs, making it difficult to distinguish causal bottlenecks from correlated
symptoms. This draft studies request lifecycle profiling: representing each
request as an ordered timeline across tokenization, queueing, prefill, decode,
streaming, and cleanup, then attributing the dominant bottleneck under
controlled fault injection. The current artifact contains the trace schema,
attribution skeleton, deterministic synthetic fault-injection harness, tests,
NPU6 preflight contract, warmup-controlled client-observed trace probe,
experiment plan, and claim ledger. It does not yet claim internal vLLM
scheduler/KV tracing, measured diagnosis accuracy, or trace overhead.
\end{abstract}

\keywords{LLM serving, observability, profiling, causal diagnosis}

\maketitle

\section{Problem}

Aggregate TTFT and TPOT report symptoms, not causes. A request may be slow
because of queueing, prefill saturation, KV allocation, decode jitter, slow
streaming, or cleanup stalls. We study whether lifecycle traces can become
auditable causal evidence for optimization work.

\section{Key Idea}

Each request emits ordered lifecycle events. The profiler converts complete
event pairs into stage spans and attributes the dominant bottleneck using an
explicit rule set that can be validated by fault-injection ground truth.

\section{Design Scope}

The first implementation provides trace primitives, schema coverage checks, and
deterministic attribution logic. The no-NPU harness covers tokenizer delay,
queueing, prefill, decode, KV pressure, streaming backpressure, and cleanup
stalls with known ground truth. The NPU6 preflight contract specifies the
endpoint, model path, authentication, Ascend runtime root, device ownership, and
trace export schema required before existing-server probes can support
client-observed online evidence. The current NPU6 probe records request
preparation, HTTP send, first streamed chunk, stream completion, and cleanup
from the probe process. Runtime claims require internal hooks for scheduler
admission, queue wait, prefill completion, decode progress, KV pressure, stream
backpressure, and cleanup.

\section{Evaluation Plan}

The evaluation will compare the profiler against raw logs, simple stage timers,
manual diagnosis, and profiler reports with causal rules disabled. Metrics
include attribution accuracy, false positives, false negatives, tracing
overhead, event coverage, and root-cause diagnosis time.

\section{Current Evidence Boundary}

No-NPU trace tests and a deterministic synthetic fault-injection matrix are
currently supported as \texttt{simulation/model} evidence. The latest synthetic
matrix reports seven of seven correct attributions with zero false positives,
zero false negatives, and zero missing-event rate.

The live NPU6 evidence is narrower. The repo-local preflight is READY, and a
warmup-controlled existing-server probe records one warmup request plus 12
measured streaming requests on the managed NPU6 endpoint. All measured requests
succeed, and the probe emits 117 client-observed lifecycle events across nine
stage names. Table~\ref{tab:npu6-trace} summarizes the generated paper asset.

\section{Claim Boundary}

The current evidence supports trace schema feasibility, synthetic attribution
coverage, and live client-observed lifecycle export. It does not yet support
claims about diagnosis accuracy on live faults, profiler overhead, internal
queue/KV attribution, or root-cause time improvement. Those claims require
paired NPU6 runs with and without profiler instrumentation, plus controlled
runtime fault injection with known ground truth.
