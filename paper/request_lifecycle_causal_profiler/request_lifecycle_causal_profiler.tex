\begin{abstract}
LLM serving slowdowns are often diagnosed from aggregate latency and scattered
logs, making it difficult to distinguish causal bottlenecks from correlated
symptoms. This draft studies request lifecycle profiling: representing each
request as an ordered timeline across tokenization, queueing, prefill, decode,
streaming, and cleanup, then attributing the dominant bottleneck under
controlled fault injection. The current artifact contains the trace schema,
attribution skeleton, tests, experiment plan, and claim ledger. It does not yet
claim measured diagnosis accuracy on live traces.
\end{abstract}

\keywords{LLM serving, observability, profiling, causal diagnosis}

\maketitle

\section{Problem}

Aggregate TTFT and TPOT report symptoms, not causes. A request may be slow
because of queueing, prefill saturation, KV allocation, decode jitter, slow
streaming, or cleanup stalls. We study whether lifecycle traces can become
auditable causal evidence for optimization work.

\section{Key Idea}

Each request emits ordered lifecycle events. The profiler converts complete
event pairs into stage spans and attributes the dominant bottleneck using an
explicit rule set that can be validated by injected-fault ground truth.

\section{Design Scope}

The first implementation provides trace primitives and deterministic attribution
logic. NPU6 runs should begin as existing-server probes before any runtime
policy uses profiler output.

\section{Evaluation Plan}

The evaluation will compare the profiler against raw logs, simple stage timers,
manual diagnosis, and profiler reports with causal rules disabled. Metrics
include attribution accuracy, false positives, false negatives, tracing
overhead, event coverage, and time-to-root-cause.

\section{Current Evidence Boundary}

Only no-NPU trace and attribution tests are currently supported. Live diagnosis
claims require manifest-backed NPU6 probes and controlled fault-injection
results.
