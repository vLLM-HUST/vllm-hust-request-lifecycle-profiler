# Agent Instructions: Request-Lifecycle Profiler

These instructions apply to the whole repository. `CONTRIBUTING.md` and
`.github/BRANCH_POLICY.md` define the ordinary contribution workflow; direct
user instructions and independently stated repository rules take precedence.

## Mission and current status

Build an optional, bounded, fail-open request-lifecycle profiler that can
normalize lifecycle events into a causal DAG, compare matched traces, rank
likely mechanisms, report confidence and unexplained residual, abstain when
evidence is insufficient, and validate non-abstained predictions with minimal
counterfactuals.

The current KV-recovery implementation is default-off and spans this profiler,
vLLM-HUST runtime PR #236, and vLLM-Ascend-HUST PR #216. G1-G6 artifacts are
development mechanism/capture results. They are not benchmark #95 accepted
performance evidence. Blind custody/reveal evaluation and the flat-summary
comparison remain incomplete, so the project status is `NOT_M0_PROVEN`.

## Development workflow

- Use the `vllm-request-lifecycle-profiler-exp` environment. Do not install
  project overlays into the shared `vllm-hust-dev` environment.
- Use `feature/<project-or-purpose>` branches and ordinary Git commits.
- Keep profiler code under `src/`, tests under `tests/`, probes under
  `.benchmarks/`, and research artifacts under `paper/` or `docs/`.
- Preserve the default disabled serving path. Serving callbacks must fail open;
  evidence validation and incomplete traces must fail closed.
- Use the pinned `third_party/llm-serving-workloads` source for trusted runs.
  The fork-safe test fixture proves only the narrow parent-side API surface and
  does not replace the dependency's own tests.
- Before submitting changes, run the relevant focused tests, the complete CPU
  suite when practical, Ruff checks, `git diff --check`, and package builds.
- Use normal code review and repository CI. Do not make ordinary development,
  testing, commits, runtime smoke, or PR progress depend on project-invented
  approval machinery.

## Retired historical process

The former project-local authority, owner-approval, approval-candidate,
co-signature, implementation-attestation, content-freeze, digest-chain, and
joint-admission framework is retired and non-normative. Historical references
may be read to understand old code or decisions, but they must not be used to
block work, request approval, or create replacement artifacts.

SHA-256 remains appropriate for ordinary data-integrity checks such as shard
content verification and for registry/spec values generated by canonical
benchmark tooling. Those uses do not create an approval system.

## Evidence and claims

Label every experiment as `real-online`, `existing-server-probe`, `replay`,
`simulation/model`, `projected-profile`, or `derived-artifact`. Use
`smoke-only` where applicable. Profiler observations are diagnosis evidence;
they do not by themselves establish a runtime speedup or M0.

Performance implementation PRs must follow the canonical cross-repository
policy in <https://github.com/vLLM-HUST/vllm-hust-benchmark/issues/95> and the
active target registry under benchmark issue #104. In particular, formal
performance evidence requires comparable accepted base/head `real-online`
artifacts, exact Git commits, complete resolved configurations, raw artifacts,
environment manifests, at least three independent service lifecycles, and all
repetitions with median and IQR. A smoke, replay, derived artifact, screenshot,
or aggregate-only table is not formal public-target evidence.

Only the centralized registry/spec hash required by that benchmark policy is a
merge-gate hash. Do not create project-local approval manifests or digest
chains.

## Current integration boundary

- Profiler PR #17 is the primary integration PR.
- Runtime PR #236 supplies the current default-off runtime ABI and connector
  wiring.
- Ascend PR #216 supplies the NPU model-runner first-compute observation.
- The ordinary CPU CI fetches runtime PR #236 head and runs ABI integration,
  the complete profiler suite, critical Ruff checks, and package builds.
- The full connector test requires a complete vLLM-HUST checkout and its test
  dependencies. When those are available, set `VLLM_HUST_FULL_SRC` to that
  checkout and rerun the connector gate.

After integration, continue with fresh opaque cases, custody/reveal blind
evaluation, a flat-summary comparison arm, and counterfactual validation.
